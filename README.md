# AI高赔率股票池（V2.4.3）

基于《项目交接》落地的可运行研究项目：固定 74 只 A 股股票池、V2.4.3 七维评分、Bear/Base/Bull 情景估值、市值—利润兑现初检、每日收盘后暂定排名，以及 8 个板块研究底稿。

> 定位：研究流程与数据底稿工具，不是投资建议，也不是已验证的最终排名。行情与财报来自公开接口；利润预测、合理 PE 和定性评分需要逐股人工覆盖。

## 快速开始

环境要求：Windows PowerShell 5.1（系统自带），无需安装 Python/Node。

```powershell
# 1) 校验股票池代码与名称（首次或改池后）
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-pool.ps1

# 2) 首次或需要更新公司画像/产品结构/公告线索时
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\fetch-profiles.ps1
#   -Force                 全量重新抓取（公司概况、主营构成、经营评述、公告）

# 3) 每日收盘后：抓行情 + 复用/刷新财报 + 评分 + 生成报告
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-daily.ps1

# 可选参数
#   -Date 2026-11-06       指定交易日（默认取上证指数最新行情时间戳）
#   -SkipQuotes            复用已有行情文件，只重算评分
#   -RefreshFinancials     强制重新抓取全部财报

# 4) 重新生成板块与个股研究底稿（改配置后运行；默认不覆盖已有个股笔记）
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-sector-docs.ps1
#   -Force                 覆盖全部个股研究文件
```

输出：

- `output/YYYY-MM-DD/report.md`：完整 1—74 名报告
- `output/YYYY-MM-DD/rank.csv`：全字段排名底稿
- `output/latest/`：最新一份报告与 CSV 的副本

## 每日工作流

1. `run-daily.ps1` 先解析最新 A 股交易日（上证指数行情时间戳，避免周末写入错误日期）。
2. 抓取 74 只股票的不复权收盘价、总市值、流通市值、PE(TTM)、PB、涨跌幅、成交额、行业。
3. 财报优先复用 `data/financials/` 最新快照；`-RefreshFinancials` 才重新抓取（营收、归母净利、营收/净利同比、毛利率、ROE、报告期）。
4. 评分引擎读取 `config/assumptions.csv`，用当日市值重算 Bear/Base/Bull 收益率与七维分数，按总分排序 1—74。
5. 输出完整榜单、前 20、重大升降、Base>40% 利润桥、板块汇总、数据缺口。

## 个股研究文件包含什么

每个 `docs/sectors/<板块>/<代码>-<名称>.md` 都包含：

1. **速览**：现排名、总分条、Base/Bull 条、市值、PE、营收、净利、同比、毛利率。
2. **公司画像**：全称、东财/证监会行业、地区、员工、董事长、注册资本、官网、主营范围、公司简介。
3. **产品结构与收入占比**：按产品/业务、按行业、按地区的最新披露收入、占比、毛利率，并用文本条形图显示占比。
4. **订单与经营动态**：从最新经营评述中自动摘录订单/产能/客户/交付线索；列出订单/合同/扩产相关公告及最近 5 条公告，附公告链接。
5. **竞争地位**：池内同业的市值、营收、净利、增速、毛利率、PE、总分对比，计算该公司在板块内的分项名次；自动摘录行业地位表述。
6. **行情、财务与估值**：收盘价、总市值、PE/PB、Forward PE、最新报告期财务。
7. **三情景、七维评分、利润桥、原始假设、尽调问题、催化与风险、证据与待核实、研究日志**。
8. **附录：经营评述全文**（F10 原文照录）。

> 在手订单没有公开的结构化字段；文件中的订单信息是公告标题与经营评述线索，不等于完整订单簿，订单金额需回查定期报告/业绩说明会/调研纪要。

## 模型实现

总分 = 收益(25) + 赔率(25) + 期权(17) + AI弹性(6) + 盈利加速(11) + 催化(7) + 确定性(9) − 风险扣分(0—20) + 凸性(0—2)，理论范围 −20—102。

- **收益分**：由重算后的 Base 收益率线性映射（−60%→0 分，+120%→25 分）。
- **赔率分**：期望收益 ÷ 下行幅度，除以阈值 2.0 封顶；Bear 低于 −60% 时打 0.8 折。
- **期权/AI/催化**：当前为板块级占位值（见 `assumptions.csv` 的 `score_option`、`score_ai`、`score_catalyst`），可逐股覆盖。
- **盈利加速**：用最近财报的归母净利同比（权重 60%）与营收同比（权重 40%）计算；缺财报时取满分一半并标注。
- **确定性**：用净利润规模、是否盈利、毛利率三项规则计算；缺财报时取满分一半。
- **风险扣分**：PE(TTM)>60 扣 6、>40 扣 3；Bear<−60% 扣 5；Base<0 扣 8；亏损再扣 6，封顶 20。
- **凸性**：Bull≥150% 且 Base≥30% 加 2；Bull≥100% 加 1。
- **情景估值**：沿用 2026-11-03 旧基准的 Bear/Base/Bull 目标市值锚，用当日市值重算收益率——这是**敏感性口径，不是重新估值**。
- **利润桥**：所需利润 = Base 目标市值 ÷ 合理 PE（默认 25×）；当前远期利润 = 旧市值 ÷ 旧 Forward PE（未填预测时）。缺口比例 ≤50% 记“通过初检”，50%—100% 记“需验证”，>100% 记“需强验证”。

## 配置说明

### config/assumptions.csv（核心维护文件）

| 字段 | 含义 |
|---|---|
| `old_rank` / `old_cap_yi` / `old_forward_pe` | 2026-11-03 旧模型基准，只作目标市值锚与变化检查，**不作为评分输入** |
| `bear_pct` / `base_pct` / `bull_pct` | 旧基准情景收益率（%），用于反推目标市值 |
| `profit_2027e` / `profit_2028e` | 人工填写的归母净利润（亿元），填后按 70%/30% 加权替代反推利润 |
| `reasonable_pe` | 利润桥合理 PE，默认 25 |
| `score_option` / `score_ai` / `score_catalyst` | 定性维度评分（0—17 / 0—6 / 0—7） |
| `score_certainty_override` / `score_earnings_override` | 覆盖规则计算值（0—9 / 0—11） |
| `risk_override` | 覆盖规则风险扣分（0—20） |
| `notes` | 研究备注 |

### 情景概率

`config/model.json` 中暂定 25%/50%/25%。《项目交接》明确用户尚未冻结权重，修改前不应把它当作正式参数。

## 数据源与口径

- 行情：东方财富 `push2.eastmoney.com` 公开行情接口（不复权现价、总市值、PE、PB）。
- 财报：东方财富 `datacenter-web.eastmoney.com` 业绩报表接口（RPT_LICO_FN_CPD）。
- 公司画像/产品结构/经营评述：东方财富 F10 `CompanySurvey` 与 `BusinessAnalysis` 接口（最新披露报告期）。
- 公告线索：东方财富公告接口 `np-anotice-stock.eastmoney.com`（近 40 条，按关键词筛选）。
- A+H、增发、股本变动等口径问题尚未自动校正；总市值采用接口返回的整体市值，需在深度研究时逐只核对。
- 每次抓取保留 `data/` 快照，报告头记录交易日与生成时间。

## 重要限制

1. 当前定性评分是板块级占位值，排名主要由估值/赔率与财报同比驱动，**不能替代逐股研究**。
2. 目标市值锚来自旧基准；股价变化会机械改变情景收益率，必须用最新利润预测重新估值。
3. 旧名次仅用于变化检查，禁止作为新评分输入。
4. 项目不包含自动推送；定时执行需由外部任务计划（如 Windows 任务计划程序）触发 `run-daily.ps1`。
5. 股票池口径冲突（晶合集成候选、76 vs 74）保持原状：仍为 74 只，未擅自增删。
6. 新莱应材保留在研究榜，但不恢复买入资格；南大光电、安集科技的历史持仓指令不代表当前持仓。
